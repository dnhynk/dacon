# 연구와 실행

## 한 라운드

개선 본체는 하나다: 루트 `script.py` → `submission/`. ZIP과 Colab 키트도 같은 본체를 쓰고, 검증된 변경은 여기에
합친다. 실험 결과와 동결 원본은 비교·롤백 기록이지 또 다른 현행 제출본이 아니다.

가설 하나 → 사전등록 → 탐침 빌드 → 제출 → 결과 기입 → 규칙대로 채택·기각·보류 → `docs/STATE.json` 갱신.

- 사전등록(`PREREGISTRATION.md`, 로컬)은 제출 **전에** 기준 패키지, 바뀌는 항목, 가설, 예상 Δ, 유지·되돌림 규칙을 적는다.
- 탐침 패키지는 기준 패키지와 `switches.py`의 값만 다르다. 기본 스위치는 LB로 잰 기준(P3a)이다.
- dev·replica 점수는 LB 변화의 부호조차 자주 틀렸다. 경보로만 쓰고, 결정은 사전등록 규칙과 공식 점수로 한다.
- 겹치지 않는 항목의 Δ를 더한 값은 조건부 추정이다. 공식 점수로 적지 않는다.
- 공고 ID·정답·데이터셋 구조(편집 흔적, 항목 동시 발화)를 규칙 조건에 넣지 않는다. 점수가 올라도 쓰지 않는다(사용자).
- 새 실행 점수가 크게 떨어지면 기능 개발보다 그 하락을 먼저 처리하고, 낮아진 값을 말없이 새 기준으로 삼지 않는다.

모델 판독(프롬프트·선택지·후보 줄)을 바꾸면 새 Gemma 응답이 필요하다. CPU 판정만 바꾸면 저장 저널을 재판정할 수
있지만, 그 결과는 재판정이라고 표시한다.

## 실행과 재현

```text
python script.py --help
python tools/build_submission.py <이름> [NAME=VALUE ...]
python -B runs/rebuild_c/transfer_20260925/replay_switch.py <실행폴더> <입력.jsonl.gz> <출력.csv> [NAME=VALUE ...]
```

- 개발 실행은 `--input`, `--data-dir`, `--model-dir`, `--output-dir`, `--journal <경로.jsonl.gz>`(또는 `PPS_C_JOURNAL`)를
  명시하고, 실행마다 새 출력 폴더를 쓴다. 저널이 없으면 원응답이 남지 않아 재판정을 할 수 없다.
- 평가 서버 실행은 `python script.py`이며 공식 `PPS_*` 경로 환경변수를 따른다.
- 저널은 파싱 실패를 포함한 모든 원응답을 남긴다. 좋은 점수가 나올 때까지 반복한 응답을 고르지 않는다.
- 빌드는 기존 ZIP을 덮어쓰지 않는다. 빌드 성공과 mock 실행은 새 점수나 L40S 시간 검증이 아니다.
- 재판정(`replay_switch.py`, 로컬)은 GPU·네트워크 없이 저장 저널을 현행 코드와 스위치로 다시 판정한다.
  기본 스위치의 재판정 결과가 기준 패키지의 저장 예측과 바이트 단위로 같아야 기본 동작이 보존된 것이다.

Windows 확인:

```powershell
.venv/Scripts/python.exe -B tools/project_status.py
.venv/Scripts/python.exe -B tools/project_status.py --verify
.venv/Scripts/python.exe -B -m pytest -q tests
```

테스트는 GPU·모델·대회 원문 없이 도는 합성 검사다. 비공개 로컬 파일이 필요한 검사는 그 파일이 없으면 건너뛴다.

## 자원과 권한

- 로컬 `docs/LOCAL_HANDOFF.md`에서 세션·GPU 소유를 먼저 확인한다. 다른 세션이 Chrome·Colab·GPU를 쓰는 동안 같은
  자원에 연결하지 않는다. 과거 보고서의 승인·타이머·Run 상태는 현재 권한이 아니다.
- GPU는 CPU 재판정으로 답할 수 없을 때만 Colab 키트(`runs/rebuild_c/colab/`)로 쓴다. 목적과 예상 시간을 먼저
  밝히고, 한 번에 한 실행, 결과를 회수한 뒤 런타임을 해제한다. 서브에이전트는 GPU를 쓰지 않는다.
- 공식 제출은 사용자의 허락이 있을 때만 한다. 라벨을 알아내려는 탐침은 제출하지 않는다. 예약 제출 스크립트는
  import만 해도 제출하므로, 내용을 보려고 실행하거나 import하지 않는다.
- 저장소는 공개다. 소스·설정·합성 테스트·집계 점수만 올린다. 제공 원문·제공 자료 사본·라벨·저장 응답·공고별
  예측·인증정보·브라우저/에이전트 로그는 올리지 않는다. 푸시 전에 새로 올라갈 객체에 제공 파일 사본과 비밀정보가
  없는지 확인한다.

## 인계

- 살아 있는 상태 문서는 둘이다. `docs/STATE.json`에는 공식 LB 원장, 현재 과제, 진입점, 제약을 둔다.
  로컬 `docs/LOCAL_HANDOFF.md`에는 세션 소유와 이어갈 작업을 둔다.
- 공식 점수가 나오면 `official.ledger`의 해당 행에 적는다. 최고점이 바뀌면 `official.best`도 바꾼다.
- 라운드의 상세 근거는 그 라운드 폴더에 남긴다. 루트 문서에 진행 이력을 덧붙이지 않는다.
- 동결 코드·증거는 옮기거나 덮어쓰지 않는다. 상태 파일을 덮어쓸 수 있는 옛 `finish*`/`checkpoint*` 스크립트는
  다시 실행하지 않는다.
