# 개발 서사 (2026-09 초 ~ 09-22): 무엇을 했고, 무엇이 틀렸고, 무엇이 정해졌나

빈 세션이 지난 몇 주의 흐름과 지금의 방향을 한 번에 이해하도록 쓴 문서다. 현재 수치와 상태의 기준은 `docs/STATE.json`과 로컬 `docs/LOCAL_HANDOFF.md`다. 이 문서는 그것들이 왜 지금처럼 되었는지를 설명한다.

## 1. 과제

- **입력과 출력:** 나라장터 입찰공고 1건마다 위반 항목 24개(v1–v24)를 0/1로 판정하고 근거 문구(e1–e24)를 낸다.
- **점수:** 항목별 F1의 평균(macro-F1)이다. 근거 열은 점수에 들어가지 않는다.
- **실행 조건:** 고정 모델 Gemma 4 26B-A4B-it, 공식 이미지 `vllm/vllm-openai:v0.26.0`, L40S 한 장이다. 비공개 1,853건을 2시간 안에 처리해야 하고, 공고마다 LLM 정상 호출이 1회 이상 있어야 한다.
- **제출:** 1일 1회, 마감 09-29다. 리더보드는 비공개 1,853건 전체 점수다. 제출 내역에서 최종 제출을 고를 수 있다.
- **제공 자료:** 라벨이 있는 dev 200건(편집된 공고 88건에 양성 153셀, 손대지 않은 공고 112건), 라벨 없는 코퍼스 2만 건, 법령·고시 원문, 베이스라인 스크립트다.
- **정답의 성격(가설 H1):** dev를 분석하면 양성은 실제 공고에 주최 측이 조항을 삽입·삭제·수정해 심은 위반이다. 음성은 손대지 않은 자연 공고다. 그래서 원래 공고에 있던 위반 상태는 정답이 0이라고 본다. 과제는 "위반 상태 찾기"가 아니라 "편집 찾기"다.

## 3. 솔직한 평가: 무엇이 의미 없었고 왜 그랬나

9월 17일 이후의 튜닝은 비공개 점수에 효과가 있었다는 근거가 없다. dev200은 +0.06, 합성 패널은 +0.05~0.10 올랐다. 그러나 정직한 측정은 0.631(40건)에서 0.651(1,853건)로 움직였을 뿐이고, 40건의 잡음을 생각하면 차이를 주장할 수 없다. 9월 초 CPU 소비기 감사도 대부분 dev160 표본 안의 변화였다.

원인은 다섯 가지다.

1. **표본 내 최적화.** 모든 개선을 튜닝에 쓴 자료로 쟀다.
   - dev200은 이미 포화였다(v1–v8, v21–v23 F1 1.0).
   - 합성 세트는 우리가 만든 분포였다.
   - 보류분은 둘 다 결국 열었다.
2. **목표 함수가 틀렸다.** 심은 표적의 재현율과 우리가 만든 near-miss 음성에 집중했다. 실제 오류의 약 2/3는 손대지 않은 공고의 오발화, 곧 원래 있던 위반 상태에 대한 발화였다. dev 음성 112건이 이 문제를 가렸다.
3. **리더보드를 쓰지 않았다.** 1일 1회 슬롯을 9월 21일까지 한 번도 쓰지 않았다. 재현율을 정직하게 재는 유일한 신호가 리더보드인데도 그랬다.
4. **수용 기준이 잘못됐다.** "dev200 퇴행 0"이 관문이었다. 그래서 포화된 dev200을 해치지 않으면서 자연 발화를 늘리는 변경이 통과했다. 셀 단위 수정은 분할을 넘어 전이되지 않았다. 예컨대 합성 A에서 만든 수정이 합성 B에서는 0셀을 바꿨다.
5. **복잡도가 늘었다.** 같은 자료로 다듬은 특수 패킷과 검토 호출이 계속 붙었다.

이 루프를 돌린 것은 작업 세션들(이 문서를 쓴 Claude 세션 포함)과 그 절차다. 감사가 경고했지만 방향을 바꾸지 않았다.

## 4. 다시 시작했어야 할 지점

**9월 17일, 개봉 전 측정(보류 40건 0.631, 발화 오류 0.325셀/공고)이 나온 시점이다.** 그때 했어야 할 일은 네 가지다.

1. dev 튜닝을 멈춘다.
2. 그날부터 매일 제출해 리더보드로 실제 수준을 확인한다.
3. 손대지 않은 자연 공고로 봉인 표본을 만들어 오발화를 재고 줄인다.
4. "자연 위반 = 정답 0" 전제를 리더보드로 먼저 검증한다.

실제로는 첫 제출(9-21) 뒤인 9월 21~22일에야 이 방향으로 재설정했다.

- **L40S 비용:** tier2 3.49초/건, tier3 2.66초/건, 엔진 준비 약 270초다.
- **모델 호출의 역할:** A1은 v1–v9, A19는 v20·v22 재현율, Q10은 v12–v17 재현율을 맡는다. A10은 부르지 않는다.

**리더보드가 정한 것**
- build_18에 넣은 정밀도 변경 묶음은 비공개 점수를 0.061 내렸다. 표본 내 재현율 보존에 기댄 발화 감축은 안전하지 않다.
- 어느 구성요소가 손해를 냈는지는 아직 모른다. 항목 묶음별 분리 제출로 가린다.
