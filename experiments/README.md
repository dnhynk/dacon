# 동결 연구 소스

루트 기본 구현을 바꾸지 않고 비교한 연구 스냅샷이다. 아래 점수는 공식 점수가
아니며, 모델 응답을 저장한 뒤 CPU에서 재판정한 개발 160건 결과다.
새 프롬프트의 성능과 저장 응답 재판정 결과를 구분해야 한다.

| 경로 | 역할 | 저장 응답 기반 기록 |
| --- | --- | --- |
| [v20_uniform_route_v1/source](v20_uniform_route_v1/source/) | 모든 공고에 기존 v20 추가 추론을 적용하는 보존 기준 | 0.718474, FP 53 / FN 28, 과거 응답 640개 |
| [precision_audit_fix_v1/source](precision_audit_fix_v1/source/) | 금액·범위·지역 등 CPU 보정 | 0.746692, FP 59 / FN 24, 과거 응답 480개 |
| [precision_joined_v1/source](precision_joined_v1/source/) | 위 CPU 보정과 기존 v20 경로의 결합 | 0.751807, FP 53 / FN 24, 과거 응답 640개 |
| [v2 CPU r3](precision_audit_fix_v2/stages/cpu_candidate_source_r3/) | 역할·구성품·동일 필드 비교 보완, 과거 응답 호환 | 새 모델 입력의 성능을 뜻하지 않음 |
| [v2 typed r3, thinking 768](precision_audit_fix_v2/stages/typed_candidate_source_r3_768/) | 상태·범위·원문 인용을 분리하는 새 모델 출력 계약 | 실제 응답 비교 완료, 인용 검증 실패로 전체 후보 비채택 |

각 소스 트리는 설정과 진입점을 포함한다. 해당 트리를 독립 실행 루트로 사용하며,
공식 배포 데이터와 지정 모델은 별도로 준비해야 한다. `script.py --help`에서
입력·모델·출력 경로를 확인할 수 있다. 루트의 제출 ZIP 생성 명령은 이 후보들을
자동 선택하지 않는다.

## 전문 기능을 발전시키는 기준

금액 비교, 자격의 논리 관계, 발급·보유·제출 시점, 구매 구성품,
지역의 역할과 포함관계, 본문–등록정보의 동일 필드 비교를 구분한다.
문장에 등장한 단어를 바로 최종 판정으로 바꾸지 않고 근거와 적용 범위를 보존한다.
형식이 맞는 모델 출력도 사실이 틀릴 수 있으므로 상태·원문 인용·판정 전제를 확인한다.
확인할 수 없는 구성품 전체나 예외를 억지로 확정하지 않는다.

기존 효과가 있는 보정을 유지하면서 전문 기능별 기여와 새 오류를 함께 측정한다.
새 오류 0을 모든 연구의 절대조건으로 두지는 않지만, 근거 없는 전체 범위 확대나
공고 ID별 정답 보정은 허용하지 않는다. 개발에 쓴 공고에서의 개선은 독립적인
새 공고 검증과 구분한다.

원본 데이터 없이 실행할 수 있는 합성 관계 검사는 다음과 같다. 실패하면 종료 코드 1을 반환한다.
이는 실제 공고의 정답이나 F1 검증을 대신하지 않는다.

```bash
python -B experiments/check_assertion_scope.py --source experiments/precision_audit_fix_v2/stages/cpu_candidate_source_r3
python -B experiments/check_multiple_region_scope.py --source experiments/precision_audit_fix_v2/stages/cpu_candidate_source_r3
```

## 새 응답 비교에서 확인된 한계

이미 노출된 개발 32건에서 A(기존 입력), C(새 입력), L(기존 v20 추가 호출)의
총 224개 응답을 새로 생성했다. 같은 응답에 대한 CPU 지역 보정은 오류 4개를
회복했지만, 기존 CPU를 고정한 채 새 입력 전체로 바꾼 비교는 회복 7개·새 오류
12개여서 전체 교체를 기각했다.

추가 L 호출을 양쪽에서 제외한 비교에서도 C의 v20 부분은 회복 5개·새 오류 0개였다.
그러나 해당 표본의 v20 양성은 1개뿐이고, 일부 회복에는 구성품 적용 범위 해석이
남는다. 이 결과만으로 새 공고에서의 정확성이나 추가 호출의 일반적인 효과를
확정하지 않는다. 입력 선택과 프롬프트 변경의 효과도 완전히 분리된 실험이 아니다.

### 후속 A/T192: 구조화 출력의 실제 소비 실패

같은 노출 32건에서 기존 입력 A와 구조화 입력 T를 항목 1–9, 10–18, 19–24별로
비교했다. 첫 요청 192개와 재시도 122개, 총 314개 실제 응답을 회수하고 동결된
CPU 코드로 최종 소비를 독립 재현했다. 최초 192개는 모두 JSON 형식 검증을
통과했지만, T의 65개는 사실의 원문 인용 검증에서 거절됐다.

| 입력 묶음 | 최초 요청 | 최초 인용 검증 실패 | 재시도 | 최종 결측 |
| --- | ---: | ---: | ---: | ---: |
| A 세 묶음 합계 | 96 | 0 | 0 | 0 |
| T 항목 1–9 | 32 | 17 | 29 | 12 |
| T 항목 10–18 | 32 | 16 | 29 | 13 |
| T 항목 19–24 | 32 | 32 | 64 | 32 |

A만 완전한 32×24 결과를 얻었다. T를 포함한 네 고정 조합은 모두 결측이 있어
전체 Macro F1을 산출하지 않았다. 특히 `generic` 또는 `non_sw`라는 확정 상태에
인용을 비우는 응답이 반복됐다. 이는 해당 판단이 모두 오답이라는 뜻이 아니라,
현 출력 계약에서 수용할 수 없었다는 관측이다. 인용 검증을 통째로 끄지 않았다.
첫 재시도는 8개 요청을 복구했지만 두 번째 재시도 57회는 추가 복구가 없었다.
모델 적재는 311.4초, 적재 포함 실행은 1074.8초였다. 환경 준비와 다운로드 허용을
기다린 자원 점유 시간은 이 실행 시간에 포함하지 않는다. 회수 후 런타임을 삭제했다.

### 별도 사후 CPU 후보: 항목 1–9의 부속 사실 실패 격리

첫 T1 응답 중 원시 v9가 0이고 MODEL 사실의 인용만 검증에 실패한 경우에 한해,
그 사실을 `unknown`으로 폐기했다. 근거를 보충하거나 원시 판정값을 바꾸지 않았고,
근거 없는 양성은 그대로 엄격히 검증했다. 17개 사실에 적용해 T1 32개를 모두
소비할 수 있었다. 다른 항목 묶음에는 기존 A 입력과 응답을 유지했다.

| 노출 32건에서의 비교 | 24항목 Macro F1 | FP / FN |
| --- | ---: | ---: |
| A1 + A10 + A19 | 0.488228 | 21 / 8 |
| T1 + 실패 격리 + A10 + A19 | 0.516005 | 20 / 7 |

회복 2개·새 오류 0개는 **새 T1 입력과 CPU 실패 격리의 결합 효과**다.
CPU 수정만으로 원시 판정의 정확도가 개선됐다는 뜻이 아니다. 고정 다섯 조합과
별도로 표시한 사후 연구 후보이며, 미노출 검증이나 개발 160건 재실행 결과가 아니다.
동결 소스에는 이 사후 후보를 덮어쓰지 않았다. 구조화 입력 전체 교체는 기각하고,
항목군별 개선과 근거 불충분 사실의 격리를 분리해 연구한다.

과거 기준 입력을 다시 실행한 답변에도 변동이 있었다. 따라서 위 0.718474와
0.751807을 새 통합 추론 성능으로 표현하지 않는다. 전체 새 추론·제출 환경의
실행시간·공식 점수는 별도로 검증해야 한다. 목표 0.85는 아직 달성하지 않았다.

원문·가공 데이터·정답·저장 응답·공고별 예측·실행 패킷·브라우저 및 에이전트 기록은
공개하지 않는다. 소스만으로 위 개발 점수를 재현할 수 있는 공개 데이터셋은 포함하지 않는다.
