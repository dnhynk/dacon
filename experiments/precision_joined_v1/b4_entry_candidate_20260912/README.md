# B4 일반 입력 연결부 — 보존 원본

현행 실행·개선은 저장소 루트 `script.py` → `submission/` 한 곳에서 합니다.
아래는 통합 전 연결부의 역사적 검증 기록이며, 현재 제출 실행 지시가 아닙니다.

현재 입력 파일과 제공 지식, 로컬 고정 모델, 출력 디렉터리를 받는 B4 연결부입니다. 새로운 판단 규칙이나 학습 결과를 추가하지 않았습니다. 생산 채택·공식 제출·이 연결부의 GPU 실행은 하지 않았습니다.

`source/script.py`가 실행 진입점입니다. `source/frozen`에는 이전 소비 코드 47개를 원본 그대로, `source/original_a`에는 원래 A 입력 생성 코드를 원본 그대로 보존했습니다. A 입력은 원래 v4 생성기로 만들고, 판정은 frozen v1 소비기로 처리합니다. L19는 원래 네 번째 입력을 사용해 v20/e20만 교체합니다. frozen 폴더의 옛 script.py를 대신 실행하면 같은 파이프라인이 아닙니다.

```text
python source/script.py --input <현재입력.jsonl.gz> --data-dir <제공지식폴더> --model-dir <로컬고정모델> --output-dir <빈출력폴더>
```

환경변수 PPS_DATA_DIR/PPS_MODEL_DIR/PPS_OUTPUT_DIR도 받습니다. 모델이나 외부 자료를 다운로드하지 않습니다. 한 엔진을 공유하며, 각 입력마다 A1/A10/A19/L19의 네 요청을 구성합니다. 기존 출력 폴더가 비어 있지 않으면 중복 실행을 거절합니다. 원본 모델 텍스트와 토큰 ID를 파싱 전에 저장하고, 기술적인 파싱 실패에만 같은 입력으로 한 번 재시도합니다. 해결되지 않은 판정은 0으로 채우지 않고 submission.csv 작성을 중단합니다.

CPU 검증 결과:

- 전체 개발160의640 messages/spans/token_ids/generation이 고정 입력과 일치합니다. coverage.ranges의 정수 키가 JSON 저장 시 문자열 키가 되는 표현 차이만 정규화했습니다.
- 실제 새 응답640개를 주입해 first/final B3·B4의15,360개 비트와 모든 근거를 재현했습니다.
- 일반 실행 흐름의 B3.csv/submission.csv 바이트도 실제 동결 결과와 동일합니다.
- 개발 목록에 없는 ID로 바꾼 입력을 처리합니다. 중복 실행 거절, 동일입력 1회 재시도, 미해결9비트의 0 채움 방지, 파싱 실패 전 native 보존 검증을 통과했습니다.

`cpu_acceptance.json`, `runtime_acceptance.json`이 검증 기록입니다. 실행용 source 코드는 과거 응답·개발 목록·연구 경로를 읽지 않습니다. 연구 경로는 검증 스크립트에만 있습니다.

이번 별도 A100 실험에서 측정된 B3/B4 점수는 모두 개발 Macro F1 **0.7064664502164502**입니다. 과거 응답 재생으로 얻었던0.751807은 다른 기록입니다. 이 CPU 연결 검증은 새 F1 측정이나 L40S 실행시간 검증이 아닙니다. 고정 소비 규칙이 남기는 v5 필수 근거 누락2건도 그대로 드러내며, 생산 적합성을 확인한 것으로 해석하지 않습니다.
